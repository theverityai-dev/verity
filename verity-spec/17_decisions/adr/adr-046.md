# Architectural Decision Record

## ADR-046: Visual language v2 — three colour systems with one job each, eight kind hues, in-house glyphs

* **Decision ID**: ADR-046
* **Status**: ACCEPTED (product owner, 2026-10-16: "yeah do in adr-046"). Additive: ADR-033 is not amended.
  The eight hue *values* stay provisional until the owner signs off the swatch sheet
  (`docs/reference/visual-language/swatches.html`); the rules in this record are in force now.
* **Numbering note**: ADR-045 is held for the pending "Mode D, client-owned managed cloud" proposal
  (`docs/deployment/client-owned-vercel-supabase.md` §9, FINISHER P2-0), so this record takes 046.
* **Question**: The product owner supplied two mockup screens (a production route detail and a shop-floor
  worklist) as "how every screen should look: colour coded, high visibility, graphic wherever data allows".
  ADR-033 fixes the surface (iOS inset cells, system colours, tint) but says nothing about how colour *encodes
  kind*, how state is drawn, which graphics are allowed, or where icons come from. What is the visual vocabulary
  that makes every screen more graphic and legible without breaking ADR-033, ADR-009 or accessibility?
* **Context**: `taskplans/127_visual_language_every_screen_redesign.md` (all 133 screens, DSEW first). Current
  state: `StateBadge` is a neutral grey pill with a coloured dot (`src/components/ui/primitives.tsx:770`);
  `icons.tsx` has about 40 hand-drawn glyphs at one stroke weight; `charts.tsx` has `Donut`, `BarStrip`, `Legend`
  and a "real values only, no smoothing" rule; `TrendChart` is unwired because no query returned its series.
  ADR-033 forbids borders, shadows, gradients and per-page colours on content and keeps semantic colours
  independent of the tint. ADR-009 closes `StateCategory` at six values and forbids reading `key` or `label` for
  behaviour. The mockups use bordered, shadowed cards; the owner chose to keep ADR-033's cells and borrow the
  structure and colour system only. The library study is `docs/reference/visual-language/library-study.md`.
* **Decision**:
  1. **ADR-033 stands unchanged.** Cells stay borderless 12px inset cells on the system grouped canvas; the tint
     defaults to `#0A84FF`; materials stay on bars and overlays only. Nothing here adds a border, shadow, gradient
     or translucency to content.
  2. **Three colour systems, one job each, never swapped.**
     * **Tint** (`--accent-seed`): interactive and selected. Buttons, links, selection, focus.
     * **State** (semantic): what condition a thing is in. Drawn only as a **state pill** or state dot, and only from
       `StateCategory` (ADR-009): Draft grey, Pending orange, Active **blue (semantic blue, not the tint)**, Blocked
       red, Completed green, Cancelled grey. A label such as "ready" never decides a colour.
       *Clarified 2026-10-16:* a KPI disc that counts things in one state (the shop-floor "Ready",
       "On hold", "Rework" discs) may take that state's pill colours. It is the state system drawn as a disc,
       not a kind hue.
     * **Kind**: what *sort of thing* it is. Eight hues, below. Used only on icon tiles, icon discs, avatars and
       chart series.
  3. **Eight kind hues, closed set.** Provisional names: indigo, purple, pink, teal, cyan, brown, mint, slate.
     Each defines `--hue-<name>-fill` (soft tile background) and `--hue-<name>-ink` (icon stroke, series colour)
     for light and dark. Constraints, enforced by a unit test beside `accent.ts`: icon ink on its fill at least 3:1
     (non-text); any text on a fill at least 4.5:1; each hue's distance from the four semantic hues and from the
     tint's default hue above a recorded threshold, so a kind colour cannot be mistaken for a state or a link. A hue
     that fails is replaced before freezing, so the names above are provisional. **A ninth hue needs an amendment to
     this ADR.** Kind hues never appear on pills, buttons, links, body text, borders, cell backgrounds, focus
     rings or status dots.
  4. **The hue is a function of the thing, not a page choice.** One file (`src/components/ui/business/domains.ts`)
     maps entity or stage kind to hue and glyph. A page cannot pick a colour; two screens showing the same kind
     show the same tile.
  5. **State pill.** A tinted opaque fill of the state colour, a dot and a word, text at least 4.5:1. Colour is
     never the only channel (dot, word and, where useful, a glyph). Words are short adjectives ("unpaid", "on hold").
     `StateBadge` is the only implementation; it gains the tint and nothing else. A roll-up (a job with several
     stages) shows the highest-attention state.
  6. **Selection and separation without borders.** A selected row or card uses a tint fill plus a 2px inside
     selection ring (the same focus/selection ring family ADR-033 already uses), never a content border. Cells are
     separated by canvas gap and iOS separators, as today.
  7. **Graphics, only on real data.** A chart or meter is drawn only from a value the page's own query returns.
     No sample, padded or smoothed series (the existing `charts.tsx` rule becomes platform rule). Where no series
     exists the page shows the number and an honest empty state, and the missing read is a "needs query" item in
     Task 127. Charts are server-rendered SVG with no chart library. Categorical series take the kind hues in one
     fixed order (more than eight series becomes a table); thresholds use state colours. Every graphic has a text
     equivalent (adjacent figures or table, `aria-label`, `<title>`), direct labels over colour-only legends where
     space allows, and honours `prefers-reduced-motion`.
  8. **Shared vocabulary, built in the shared layer only.** `IconTile`/`IconDisc`, tinted `StateBadge`, `StatTile`
     with icon disc, `EntityHeader`, `Breadcrumb`, `JourneyMap` (snake wrap on wide screens, vertical on phones),
     `StepProgress`, `ProgressRing`/`ProgressBar`, `FilterChips` (icon and count), `MasterDetail` and `DetailPane`
     (pane becomes a bottom sheet on phones), `ChecklistRows`, `ActionBar` (proceed filled, defer gray, reverse
     red-tinted), `Sparkline`/`AreaTrend`, `StackedBar`, `Gauge`, `FunnelChart`, `HeatCalendar`, `Waterfall`,
     `Timeline`, `Avatar`. Pages compose these; no page-local colours or one-off patterns.
  9. **Verity Glyphs, in-house icons.** Verity draws and owns its icon set. Libraries are studied for grid,
     weight, terminals and metaphor; **no third-party path data is copied and no third-party icon package is added.**
     Apple's SF Symbols are a visual target only and are never embedded or traced. Stroke is defined per size
     (16, 20, 24, 32), glyphs have outline and filled states, names describe meaning in Verity
     (`stage-winding`), and every glyph is `aria-hidden` with a visible label beside it. Delivered through the
     existing `icons.tsx` mechanism.
  10. **Presentation only.** This ADR changes how data is shown. It adds no command, entity, permission or write
      path, does not touch `enforcePolicy()`, tenancy or RLS, and on public surfaces (ADR-030 passport, ADR-042
      self-order) changes presentation only, never the token or definer path.
* **What this is not**: not a change to ADR-033's cell, canvas, typography, motion or materials rules; not a new
  accent; not a change to the monochrome mark (ADR-012); not a licence to colour a page decoratively; not a
  dependency decision for any chart or icon library (there is none).
* **Consequences**:
  * Tokens added in `src/app/globals.css` (kind hues, state fill/ink/dot), mapped once in `domains.ts`; a token
    contrast and distinctness test; geometry tests for each chart; state-to-colour map test.
  * `StateBadge`, `StatTile`/`StatCard` and `FilterChipRow` change in place so existing pages inherit the look; new
    components land in `primitives.tsx` and `src/components/ui/`.
  * `icons.tsx` grows from about 40 to about 130 glyphs over the programme (about 55 needed for DSEW), with a
    generated contact sheet for review.
  * `verity-spec/09_experience/design-system.md` gains requirement IDs for the vocabulary above in Phase 1; the
    `verity-design-companion` skill is resynced to read ADR-046 alongside ADR-033.
  * Anti-regression list (from `CLAUDE.md`) is re-run at every phase: no content translucency, gradients, glows,
    light-weight numerals, hard-coded tint, semantic colour equal to the tint, or per-page colour outside tokens.
* **Open for the product owner**: sign off the hue *values* from the swatch sheet.
* **Rejected**: bordered and shadowed cards as in the mockups (ADR-033 kept); a third-party icon package or copied
  path data (licence notices, visual drift, dependency); a free per-page choice of accent colours (the
  "everything configurable" extreme `CLAUDE.md` warns against); colour on pills or buttons from the kind hues (it
  would blur state and kind); colouring state from its label (breaks ADR-009); a chart library (bundle weight and a
  second styling system); decorative charts with invented data (breaks the honesty rule).
