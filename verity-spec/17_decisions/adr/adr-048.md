# Architectural Decision Record

## ADR-048: Controlled engineering documents are a capability of their own, distinct from Evidence

* **Decision ID**: ADR-048
* **Status**: PROPOSED (2026-10-18). Not accepted: it introduces a new capability with its own tables, a
  numbering allocator and a download audit log, so it needs the product owner's decision before any
  migration is written (`CLAUDE.md` stop conditions).
* **Review, 2026-10-18**: **design direction accepted with scope limits; the ADR stays PROPOSED.** Implementation
  (M2) is **not authorised**: it needs a recorded, narrow scope amendment (see `clients/dsew/decisions.md`) and
  the client inputs it depends on.
* **Scope limits required before implementation**
  * Documents carry identifier, revision history, controlled states, approvers, timestamps and audit history.
  * Jobs and manufacturing records reference the **exact document revision used**, never "the latest".
  * Specify draft, review, release and supersession behaviour, including what happens to jobs already in
    progress when a new revision is released (default: they keep the revision they were issued with and show a
    banner that a newer release exists; moving to the new revision is a deliberate audited action).
  * Reuse existing storage, tenancy and authorization; no second mechanism.
  * Immutable evidence and attachments stay distinct from controlled-document metadata and lifecycle; history of a
    superseded document is preserved.
  * Write the **minimum DSEW document set** before coding. Deferred: CAD integration, drawing viewers, OCR and
    full-text search, transmittals, e-signatures, and anything the client has not asked for.
* **Question**: D & S Electric Works needs drawings, specifications, procedures and reports to carry a
  number, a revision, a review and release state, links to jobs and BOMs, and a record of who opened them.
  Verity has `Evidence`, which is immutable captured field data. Is Evidence enough, or is a controlled
  document a different thing?
* **Context** (read 2026-10-18): `Evidence` rows are immutable facts (photo, document, signature, geo point,
  reading) with a stored file whose checksum is frozen; they have no number, revision, approval or release
  state. Platform file storage exists and is bound. Per-tenant running numbers already use a transaction
  advisory lock (`runtime/document-number.ts`, used for job numbers). The `approval` capability gives a
  role-named sequential chain. ADR-037 provides client-owned export.
* **Decision**:
  1. **A new capability, `verity.capability.document`.** It owns `document_type`, `document`,
     `document_revision`, `document_link`, `document_number_counter`, `document_access_log`. Evidence is not
     reused or changed: a captured photo is a fact, a controlled document is a managed artefact.
  2. **Number.** Allocated once per document by the existing advisory-lock allocator from a per-type
     pattern (`{TYPE}`, `{YEAR}`, `{SEQ:n}`, `{JOB}`), configurable by an administrator. A number is never
     reused or edited.
  3. **Revision lifecycle** through the state runtime: `draft`, `in_review`, `released`, `superseded`,
     `obsolete`. A revision's file is fixed when submitted. A released revision is immutable; a change is a new
     revision with a mandatory reason. Releasing a revision supersedes the previous one in one transaction.
     Immutability is enforced in commands and by trigger, the same way as ADR-047.
  4. **Approval** by the `approval` capability, a separate permission to release, self-approval refused by
     default with an audited exception.
  5. **Links** by `(entity_key, entity_id)`, the keyed-reference style `Evidence` already uses, to a job, BOM
     revision, order or test record. A link never moves; a superseded revision stays linked and is shown with
     a banner.
  6. **Access audit.** Opening or downloading a revision appends a row to `document_access_log` (actor,
     revision, time). It is append-only by trigger and insert-only policy. Reads are subject to
     `enforcePolicy()` like every other read; classification (internal or customer-facing) is a field, and
     customer-facing release is not a public surface (no change to ADR-030's scope).
  7. **Tenancy.** Every table has `tenant_id`, RLS enabled and forced, and a cross-tenant negative test.
     Files live in tenant-scoped storage objects.
* **Alternatives considered**
  * Treat `Evidence` of kind `Document` as the controlled document: gives immutability but no number,
    revision, review or release, so it cannot express "the current drawing". Rejected.
  * Adopt an external document system (Paperless-ngx, Mayan EDMS, Nextcloud): a second tenancy and
    authorization surface (the reason ADR-019 rejected Payload), duplicate job and customer records, and an
    audit trail Verity cannot prove. They may still be studied for ingestion and OCR ideas. Rejected as the
    controlled-document system.
  * Store documents as custom fields on jobs: no revision, no numbering, no access log. Rejected.
* **Rationale**: controlled documents are reusable beyond DSEW (any engineered-to-order client), they must
  share one tenancy and permission model with jobs and BOMs, and the guarantee "this was the released
  revision" has to be provable from the same database.
* **Consequences**: new tables and migration M2, a numbering pattern parser with tests (concurrency, no
  duplicates), a register and detail screens, a job tab and release-pack panel, permission set (author,
  release, read, administer numbering), tests for lifecycle, immutability, numbering races, link integrity,
  access log, cross-tenant isolation. Transmittals, OCR and full-text search, CAD preview and e-signatures
  are separate, estimated work and are not part of this decision.
* **Migration implications**: additive only (new tables, no existing table touched); rollback is dropping
  the new tables; no backfill. DSEW's existing numbering convention is unknown (client decision), so the
  pattern language is a design input that may change before the first migration.
* **What this is not**: not a change to INV-001, ADR-017 or `enforcePolicy()`; not a public read surface; not
  a replacement for `Evidence`.
* **Related**: ADR-017, ADR-019, ADR-030, ADR-037, ADR-047, `clients/dsew/phase1-design.md`.
