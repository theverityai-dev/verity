# Architectural Decision Record

## ADR-056: AI dependencies, untrusted documents, general-purpose model calls, and the provider gate

* **Decision ID**: ADR-056
* **Status**: ACCEPTED (2026-10-24). Extends ADR-019 (no second application framework with its own data layer) to agent
  frameworks, and answers the condition ADR-027 left open ("a general-purpose LLM call from a capability needs its own ADR").
  Supersedes nothing. Decided under the product owner's delegation of 2026-10-24 ("decide for me"). The evaluation bars in
  clause 5 are the author's initial choice and may be changed by the product owner without a new ADR.
* **Question**: Verity wants agentic features. A pasted recommendation proposed adopting Mastra or LangGraph (with Pydantic AI,
  CrewAI or Dify as options). The research of 2026-10-24 (`reports/Verity agent framework choice.md`) tested that against the
  code and the decisions already taken. Which AI dependencies may Verity take, how is content that Verity did not author treated,
  who may call a model from a capability, and how is a model provider chosen?
* **Context** (read 2026-10-24):
  * `agent-chat.ts` is a working tool-calling loop over plain `fetch` to an OpenAI-compatible endpoint. Its failures are on the
    provider side (Task 113: free-tier 8,000 tokens per minute, unreliable forced tool calls), not in orchestration.
  * Mastra (`PostgresStore`) and LangGraph.js (`PostgresSaver`) create their own tables with no tenant column and no row-level
    security. Adopting either puts agent state, and the approve decision, outside `withTenant()` and `enforcePolicy()`: the
    objection ADR-019 recorded against Payload. About 141 `@mastra/*` packages were published malicious on 2026-06-17 through a
    former contributor's npm account. Dify forbids multi-tenant operation without written authorization (one tenant is one
    workspace). Flowise was archived on 2026-08-13 with unpatched advisories.
  * The Vercel AI SDK (`ai` 7.x, Apache-2.0, ESM, Node 22 or later) is a model-I/O and streaming library with three small
    dependencies. It has a built-in approval API that keeps pending state in client-held messages, and that API was changed once
    and patched once for a signature flaw.
  * Supplier PDFs, emails and customer messages are the realistic prompt-injection path into an ERP (EchoLeak against Microsoft 365
    Copilot, ForcedLeak against Salesforce Agentforce). Task 119 and ADR-027 already bound what may leave the platform.
* **Decision**:
  1. **No agent framework owns state, orchestration, storage or authorization.** That excludes Mastra, LangGraph, CrewAI, Dify,
     Flowise and anything similar, for the reasons ADR-019 gave. Pending approvals live in ADR-055's tables; the loop stays in
     `agent-chat.ts`. A framework is reconsidered only if Task 95 phases 4 to 6 (unattended, long-running agents) are authorized.
  2. **Component libraries are allowed** when all hold: a permissive licence (MIT or Apache-2.0); an exact pinned version, taken no
     sooner than 14 days after its release; installed without lifecycle scripts (`npm ci --ignore-scripts`); no persistent store of
     its own; no network call except the configured model endpoint; no telemetry. The first candidate is the Vercel AI SDK (`ai`
     with `@ai-sdk/openai-compatible`) as a model-I/O and streaming adapter only. It is adopted when streaming, or a provider that
     is not OpenAI-compatible, is built, behind the existing agent tests unchanged. Its tools are passed without `execute`, so
     Verity runs every call through `executeCommand` and `executeQuery`; its `toolApproval` and workflow agent are not used.
     Promptfoo (MIT) is a development and CI tool, pinned, never in the production image. Patterns from 12-factor-agents are cited,
     not copied (its prose is CC BY-SA 4.0).
  3. **Untrusted content is data.** A supplier PDF, an inbound email or message, an uploaded document and any free text a person or
     a counterparty typed is untrusted. Rules for every feature that sends such content to a model:
     * The call that reads it has **no tools**. Extraction returns a typed result, validated by a schema, and nothing else.
     * The result is shown to the person beside the source text, as a proposal. Anything it leads to is a `confirm`-class action
       (ADR-055), whatever the command's normal class.
     * The content goes in a user-turn message wrapped as untrusted data, never in the system prompt.
     * Size and page limits apply before the call. A document is never fetched from a URL the document itself supplies.
  4. **General-purpose model calls from a capability** (outside the chat agent) are allowed under ADR-027's seven constraints:
     HTTP only, a per-tenant opt-in before any data leaves the platform, the minimum projection of fields, an audit row for every
     call, and a working non-AI fallback. Each use adds a short addendum naming the projection. On an on-premises host (Mode B) no
     model runs and nothing leaves (ADR-054 clause 6).
  5. **The provider is an environment setting, chosen by an evaluation gate.** `OPENAI_BASE_URL` and `OPENAI_MODEL` stay the
     configuration. A production hosted deployment uses a paid tier with written non-training and retention terms and a processor
     agreement the client can cite under the DPDP Act, before any real client data reaches it. A candidate model is accepted only
     if, on the fixed scenario suite (Task 131 phase E), it reaches at least 95% correct tool selection on single-step read
     scenarios, accepts no ungrounded write, produces no policy bypass, and refuses every injection scenario. Results are kept in
     `docs/ai/provider-evals/`. Candidates are tried in this order: the current endpoint on a paid tier (no code change); a
     second OpenAI-compatible provider; then a native provider through the clause 2 adapter.
* **Constraints**:
  1. ADR-017 stands: the agent is the caller. ADR-019 stands and is extended, not relaxed.
  2. Nothing here adds a dependency; clause 2 is the condition for adding one later.
  3. A dependency that fails clause 2 needs its own ADR before code (Stop conditions in `CLAUDE.md`).
* **Consequences**:
  * The comment in `agent-chat.ts` ("No SDK dependency added") remains true until a streaming or non-compatible-provider task
    adopts the adapter; the reason it gives changes then, and the comment is updated in that commit.
  * Document-assisted quotation or procurement (the DSEW and Document-assistant ideas) cannot start without a feature-specific
    projection and review step under clause 3.
* **Review**: reopen when Task 95 phase 4 to 6 is authorized, when a framework changes its storage to accept a caller-supplied
  tenant-scoped connection and ships a tenant-aware store, or when the evaluation gate shows no accepted model within 90 days.
