Why a module can cost more in the MVP than in the Complete ERP. Compare line by line and several MVP modules (for example CRM, document management, manufacturing execution) are priced above their Complete counterparts. Two reasons. First, each MVP module line is the whole price of that module built on its own as a working core: its screens, rules, printed formats and its AI adapter, with the shared pieces (sign-in, numbering, workflow, the adapter layer) built for the first time inside it. In the Complete ERP those shared pieces are built once and priced in the separate implementation lines (architecture ₹25,000, UI/UX and workflow configuration ₹20,000, cross-module integration ₹25,000, governance ₹10,000), so each module line carries only the module itself. Second, AI adaptability is included in every module line in both options, which raises every line above the cost of the same module without it. The Complete ERP's total is higher because it has 19 modules and deeper workflows, not because each module costs more.

What AI means for DSEW's server

The ERP is sized for one VM of 4 vCPU, 16 GB RAM and 500 GB (document 2). AI is a much heavier workload than the ERP itself, and the two cannot share a small server without one affecting the other.

  • Search and indexing on the ERP VM. Building and refreshing the semantic search index is CPU and memory intensive and runs on the same VM as live work. With it the VM needs about 4 to 6 vCPU and 32 GB RAM, plus index storage, twice the memory of the ERP alone. Indexing is throttled and paused when users are busy, so it falls behind on a busy day.
  • Language models cannot run on a standard office server. Drafting needs a local language model. On CPU alone, even a small model takes minutes rather than seconds per answer and holds the server's cores while it runs. Interactive use needs a separate on-premises workstation with a GPU of about 16 GB, which DSEW buys, houses, powers, cools, maintains and eventually replaces. We do not recommend sharing a GPU with the ERP VM.
  • Smaller local models give weaker drafts. Each use case is accepted only against its threshold on DSEW's own sample documents.
  • External services avoid the GPU but not the cost. Each use sends DSEW's documents (quotations, prices, drawings) to the provider's servers, needs a reliable internet link, and is charged per use by the provider.

AI is never needed for any ERP workflow to run, and nothing in the ERP slows down for it by design. Whether to switch AI on, and at which tier, is decided with DSEW after the use-case survey, with the hardware cost in front of it. Local models carry no usage charges but need the hardware above. External services are optional, charged by their providers, and off unless DSEW enables them. Their charges and any local GPU hardware are not in the fee.
